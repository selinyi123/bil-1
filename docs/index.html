01 · 能力

抽奖不该耗掉你整晚 Binggo 帮你扛

主能力

I

自动找活动

Binggo 会从合集增量同步并靠监控名单补上转发漏网，把进行中的抽奖先收进活动库，省掉你自己翻合集、刷动态去挖的功夫。

II

一键 / 三连

互动、转发、预约都在同一张列表里点完，三连还能一次带走多条未参加，让 Binggo 把「一条条点」收成「一次点完」。

III

自动参与

到点后 Binggo 会去点你指定的参与入口，把更新、筛选、参与串成一条线，不必你一直盯着屏幕等倒计时。

更多能力

IV

定时点击

开奖前或预约节点，Binggo 到点自动点控制台按钮；若已有任务在跑则撞车即停，不会打断进行中的流程。

V

只存本机

Binggo 控制台只响应本机 127.0.0.1，Cookie 与活动库都留在你电脑上，不往云端同步。

VI

夜间模式

侧栏一键切换亮暗主题，Binggo 会把偏好记在本机，夜里长刷活动库时眼睛更轻松。

2 · 安装并打开

安装或解压后启动 Binggo，一般会自动打开浏览器进入控制台。控制台在本机占用端口 8181（地址 http://127.0.0.1:8181，只监听本机，不会暴露到局域网）。若浏览器没自动打开，请手动在地址栏输入该地址后回车。

  1. Windows 安装版：双击 exe → 允许安装 → 从开始菜单或桌面打开 Binggo。
  2. Windows 便携版：解压 zip → 进入文件夹 → 双击带 Binggo 字样的主程序。
  3. macOS：从 dmg 拖入「应用程序」后打开；若被拦截，右键图标 → 打开（仅首次）。
  4. SmartScreen 提示：选「更多信息」→「仍要运行」（未签名软件的常见提示）。

3 · 扫码登录

在控制台左侧边栏最下方点「扫码登录」，用手机哔哩哔哩扫一扫并确认；再到「概览」看是否出现昵称与头像。此处不用输入密码，Cookie 只保存在本机。登录后「活动」可能仍为空，在第 5 步更新数据源后才会有列表。

4 · 配置 LLM

登录后需要完成 LLM 配置并测试通过，才能正常使用更新、参与等功能（解析转发抽奖正文也依赖它）。在「概览」打开「LLM 配置」，依次填写下面三项 → 点「测试」→ 再「保存」。

  1. API Key：你的模型服务商提供的密钥（只保存在本机）。
  2. 接口地址：兼容 OpenAI 格式的 API 根地址，按服务商文档填写。
  3. 模型名称：填你要调用的模型 ID。这里只做抽奖正文解析，便宜的文本模型就够用（例如 DeepSeek-V4-Flash）。

5 · 日常如何使用

建议顺序：数据源拉活动 → 活动页参与 → 可选开启定时调度 → 用任务日志盯进度。

UP 合集

  1. 左侧进「数据源」上半部分，内置多个 UP 抽奖合集专栏。
  2. 可以点一键更新活动链接一次更新全部合集；日常更建议对需要的源逐个点更新此源，更稳、不易触发限流。

监控用户动态

  1. 下半部分用于关注常参与活动、会转发抽奖的 UP，补上合集没收录的动态。
  2. 在用户空间页打开目标 UP，从浏览器地址栏链接里摘取那串数字 MID，填入名单后点「更新监控用户动态」。

活动

  1. 左侧进「活动」，按类型/状态筛选或搜奖品名。
  2. 单条点「参与」，或筛「未参加」后点顶部三连参与（最多 3 条）。充电抽奖会自动跳过。

参与文案

  1. 在「概览」设置参与文案：固定句子，或「随机借用评论」（不足时用兜底文案）。

定时调度

  1. 点右下角定时点击面板，按说明启动调度（不用时可停止）。
  2. 调度只会自动点这四类操作：「一键更新活动链接」「更新监控用户动态」「刷新任务状态」「三连参与」。
  3. 更新类在每天 0、3、6、9、12、15、18、21 点整点批次触发；三连参与在每小时 5、10、15…55 分（每 5 分钟）尝试触发。
  4. 若到点时控制台里已有别的任务在跑（撞车），调度会自动停机，但不会取消正在执行的那次抽奖任务。

任务日志

  1. 右下角任务日志查看当前任务输出；出错时可对照最后几行排查。

「刷新任务状态」只更新已有活动的参加/开奖结果，不会拉取新活动。

更细的页面说明见 控制台使用指南（console.md）。

Release 提供 Windows（安装包与便携 zip）和 macOS Apple Silicon（arm64）的 dmg / zip。Intel Mac 请查看仓库说明，或自行用源码运行。

账号与数据

不是。Binggo 是社区开源工具，与 B 站无任何合作关系；是否使用、使用频率请自行判断并遵守平台规则。

不会上传到项目方服务器。控制台只在本机监听（开发环境 127.0.0.1:8787，安装包一般为 8181），Cookie 与 llm.env 写在电脑本地数据目录。

不会混在一起。参与记录按登录 UID 分目录保存，换号后读取的是新账号对应的数据。

列表与配置

常见原因是还没登录，或还没拉过数据源。先扫码登录，再在「数据源」对某个来源点「更新此源」，或执行「一键更新」。

解析转发抽奖动态时需要模型读正文；互动、预约类走 B 站官方接口，不消耗 LLM。控制台要求 LLM 测试通过后才能正常使用更新、参与等功能。

参与与预期

不能。Binggo 帮你发现活动、减少重复翻页和点击；是否中奖仍取决于 UP 主规则与平台判定。

多为 Cookie 过期或 B 站风控。请在控制台重新扫码登录；若仍出现，先降低操作频率、避免短时间大量自动参与，再重试。

只会在设定时间触发控制台里已有的几类操作：一键更新活动链接、更新监控用户动态、刷新任务状态、三连参与。不会修改密码或隐私设置。
