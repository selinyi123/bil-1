# Account Isolation Boundary v1

日期：2026-08-12

## 结论

本切片把账号绑定 Job 的“执行身份”从动态的当前 Cookie/当前活动账号，收敛为一次 Job 执行期间不可变的 `AccountContext`。

当前只覆盖 `participate` 与 `participate_triple`。Job 数据库只保存 `account_uid`，不保存 Cookie、CSRF、代理 URL 或任何秘密。

## 已完成

- `src/account_context.py`
  - 捕获 UID、Cookie、CSRF、账号代理、Cookie 非敏感指纹和捕获时间。
  - `AccountContext` 使用 frozen/slots；秘密字段不参与 repr 和比较。
  - Cookie UID 缺失、CSRF 缺失或与 Job 绑定 UID 不一致时 fail-closed。
- `src/bilibili_client.py`
  - 绑定上下文的客户端只使用快照中的 Cookie、CSRF、UID 和代理。
  - 未绑定上下文的旧调用仍保留当前 Cookie/当前 UID 兼容行为。
- `web/job_runner.py`
  - 账号绑定的参与 Job 在 worker 内捕获上下文，并把同一个上下文传给动作层。
  - 身份错配归类为 `error_kind=identity`，不进入参与动作。
- `web/actions.py` 与 `src/participation.py`
  - 单次参与和三连参与显式传递 `account_uid`。
  - 三连的每个线程各自创建客户端，但共享同一个不可变上下文；不共享 HTTP client。
  - 旧调用不传上下文时继续使用兼容包装。
- `src/participation_store.py` 与 `src/user_settings.py`
  - 新增按 UID 读取/写入接口，旧的“当前账号”接口保留为 wrapper。
  - 参与文案读取可以绑定到 Job UID，不依赖执行中途的活动账号。
- `src/participate_preflight.py` 与 `src/status_refresh.py`
  - 账号绑定预检读取对应 UID 的参与记录。
  - live 预检返回账号视角的分类结果，但不把 `activity_status`、`platform_participated` 等账号派生字段写入共享活动行。
- 参与结果持久化
  - 账号绑定路径仍在同一事务内写 `participation_actions` 与 `participations`。
  - 共享 `activities` 行只由旧兼容路径镜像更新，绑定路径不会把账号 A 的“已参加”扩散给账号 B。

## 明确未迁移

这些项目不是本切片的隐式承诺，必须在后续规划中单独设计和验收：

1. A→B→C 自动轮换、账号健康度、隔离并行策略。
2. `participate_enhance` 和通知策略的 per-account 持久化/快照。
3. Line 长生命周期 registry。
4. AI comment、`only_followed`、`randomDynamic` 产品迁移。
5. `check_prize`、`clear_follows` 等其他账号态动作的完整 Context 化。
6. 新数据库 schema 版本；本切片没有引入 v5。

## 验收不变量

- Cookie UID 与 Job UID 不一致时，不产生 B 站请求，也不调用 `run_action`。
- `repr(AccountContext)` 不出现 Cookie、CSRF、SESSDATA 或代理认证信息。
- 一个账号绑定 Job 的成功记录只能写入它自己的 `ParticipationRow.uid`。
- 账号绑定 Job 不得把共享活动行改成该账号的“已参加”。
- 三连执行的所有目标必须使用同一个上下文对象，但每个线程拥有独立客户端。
- 旧 UI/测试直接调用参与函数时，不要求立即提供上下文。
