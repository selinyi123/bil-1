### 0.2 重要区分：「专栏 cv」vs「Opus 帖」

用户将后四个源都归在「upload/opus」标签页下，但**技术形态并不相同**：

| 类型 | URL 形态 | 适用数据源 | 列表 API 线索 |
|------|----------|------------|---------------|
| 专栏文章 | `https://www.bilibili.com/read/cv{cv_id}` | DS-2、DS-3、DS-4 | `x/article/metas?mid=` |
| Opus 图文帖 | `https://www.bilibili.com/opus/{opus_id}` | DS-5（主）；DS-2/3/4 正文内链接目标 | `polymer/.../feed/space` 或空间 Opus 列表 |

**结论**：发现层需要两套「容器解析器」（cv 解析器、opus 帖解析器），但**活动链接本身**都指向他人的抽奖动态，最终统一为 `dynamic_id`。

### 0.3 三类活动基线（产品分类）

后续参与逻辑统一按三种基类实现：

| 基类 | B 站官方含义 | 典型参与动作 | 识别优先级 |
|------|-------------|-------------|------------|
| **转发抽奖** | 动态抽奖，需转发（通常还需关注/评论） | 关注 + 转发 + 评论（按文案） | 数据源分区标题 → `lottery_notice` → 动态 `RICH_TEXT_NODE_TYPE_LOTTERY` |
| **预约抽奖** | 预约类抽奖 / 直播预约联动 | 点击预约 | 分区标题「预约抽奖」→ 动态 `additional.reserve` |
| **互动抽奖** | 官方互动抽奖组件 | 关注 + 转发 + 评论（一键参与） | 分区标题 / 视频标签 → `lottery_notice.status==0` |

**扩展类型映射**（数据源里出现、需归入三基类）：

| 数据源原文 | 建议映射 | 理由 |
|----------|----------|------|
| 充电抽奖（番茄薯条喵、互动抽奖娘） | **互动抽奖** | 需充电后参与，仍属官方组件变体 |
| 官方抽奖 / 官抽（番茄薯条喵） | **互动抽奖** | `lottery_notice` 有数据 |
| 非官方抽奖 / 非方官方（番茄薯条喵） | **转发抽奖** | 多为 UP 自发转发规则，无官方组件 |
| 置顶抽奖（工具人、J君名） | **转发抽奖**（默认） | 工具人自述「几乎都是非官方」；最终以 API 校验 |
| 视频简介「互动抽奖入口」（DS-1） | **互动抽奖**（默认） | 周报定位即官方互动抽奖合集 |

## 1. DS-1：哔哩抽奖小助理（视频简介）

### 1.1 基本信息

- **空间**：https://space.bilibili.com/885439/upload/video  
- **定位**：每周「抽奖周报」，在**最新视频简介**里维护当期可参与的官方互动抽奖清单  
- **粉丝**：约 4.7 万  
- **样本视频**：
  - [BV1Z6j76dEKC](https://www.bilibili.com/video/BV1Z6j76dEKC) — 2026-06-20，06.22–06.28 开奖
  - [BV1LyrgBtEhH](https://www.bilibili.com/video/BV1LyrgBtEhH) — 2026-01-10，01.12–01.18 开奖

### 1.2 更新特点

- **唯一数据源**不在专栏/动态帖，而在 `view.desc`（视频简介字段）
- 标题固定模式：`【抽奖周报】互动抽奖入口{起止日期}开奖，本周奖品有 {摘要奖品}`
- 每期简介开头有固定话术：`【抽奖秘籍】听说三连可以增加幸运值哦~`
- 高价值奖品用 `🔥` 前缀标注（便于人工筛选，解析时可记录 `is_highlight`）
- 更新频率低于专栏系（周更），但单条信息密度高、格式最规整

### 1.3 简介排版结构

纯文本一段流，**无 HTML 分段**。每条抽奖占一行或连续拼接，模式高度一致：

```
{开奖月日} {短链}奖品：{奖品描述}[，来自up主：{UP名}][ x数量，{UP名}]
```

**实测样例（原文片段）**：

```
06月22日 https://t.bilibili.com/1205230628579049477奖品：明日方舟：终末地-贴纸包-"没问题" x10，明日方舟终末地
06月25日 https://t.bilibili.com/1207427568768122904奖品：🔥拯救者Y900 13 16+512 x1，翼王
01月15日 https://t.bilibili.com/1152500950014885890奖品：红魔11 Pro+，来自up主：老师好我叫何同学
```

字段拆解：

| 字段 | 示例 | 是否必须 |
|------|------|----------|
| 开奖日期 | `06月22日` / `01月15日` | 几乎每条都有 |
| 活动短链 | `https://t.bilibili.com/1205230628579049477` | **必须** |
| 奖品 | `奖品：🔥拯救者Y900...` | 有 |
| 发起 UP | `来自up主：翼王` 或 `，翼王` 结尾 | 多数有 |

### 1.4 链接形态（与其他源的核心差异）

- 使用 **`t.bilibili.com` 短链**，不是 `bilibili.com/opus/...`
- 短链路径为 **19 位数字**，与 Opus 动态 ID 同族，跳转后落到 `https://www.bilibili.com/opus/{id}`
- **不会**在简介里直接出现 `bilibili.com/opus/` 字样

### 1.5 专属正则方案

#### 主提取正则（推荐）

```regex
(?P<date>\d{2}月\d{2}日)\s+
(?P<url>https://t\.bilibili\.com/(?P<dynamic_id>\d{19}))
(?:奖品：(?P<prize>[^，\n]+))?
(?:，来自up主：(?P<sender>[^\s，\n]+))?
```

#### 宽松提取（仅要链接时）

```regex
https://t\.bilibili\.com/(\d{19})
```

#### 归一化规则

```text
输入: https://t.bilibili.com/1205230628579049477
输出: dynamic_id = 1205230628579049477
      source_url = https://www.bilibili.com/opus/1205230628579049477
```

#### 分类规则

- 数据源**不显式**区分三基类；视频标签含 `互动抽奖`，**默认 `lottery_type = 互动抽奖`**
- 用 `lottery_notice` 二次确认；若仅有 `reserve` 无 lottery，则改判 `预约抽奖`

### 1.6 噪声与边界

| 情况 | 处理 |
|------|------|
| 简介里的 `#标签`、空间链接 | 不匹配 t.bilibili.com 19 位规则，自然排除 |
| `🔥` 符号 | 保留在 prize 字段，不影响 ID 提取 |
| 同一 ID 重复 | 按 dynamic_id 去重 |
| 旧视频 | 只处理 `space/arc/search` 按 `pubdate` 排序的第 1 条（或最近 N 期内未处理过的） |

### 1.7 发现层接口线索

```http
GET https://api.bilibili.com/x/space/arc/search?mid=885439&pn=1&ps=5&order=pubdate
GET https://api.bilibili.com/x/web-interface/view?bvid={bvid}   # 取 desc 字段
```

注意：空间接口可能触发 `412`，需带完整浏览器 UA / Cookie。

## 2. DS-2：番茄薯条喵（专栏 cv）

### 2.1 基本信息

- **空间**：https://space.bilibili.com/3546836235193146/upload/opus  
- **样本**：[cv51375456](https://www.bilibili.com/read/cv51375456) —《互动抽奖合集(7.12-7.13)》  
- **文集**：「共 191 篇」类合集

### 2.2 更新特点

- 隔日更新，标题带日期区间：`互动抽奖合集(7.12-7.13)`
- 文首有**统计摘要**：`本期充电2+预约6+官抽63+非官抽69`
- 文首链接「上期传送门」指向上期 cv/opus（**不是**抽奖活动，应排除）
- **唯一明确三分区 + 充电区** 的专栏源（与 DS-5 结构最像）

### 2.3 排版结构（层级）

```text
# 本期充电2+预约6+官抽63+非官抽69
# 上期传送门：...opus/...          ← 排除

# 充电抽奖
注：点网页链接，关注，充电，即可参与
# 7.12
1) {奖品名} → opus 链接
# 7.13
2) ...

# 预约抽奖
注：点网页链接，预约，即可参与
# 7.12
1) ...

# 互动抽奖
注:点网页链接,关注 转发 评论,即可参与抽奖
# 官方抽奖
# 7.12
{奖品名} → opus 链接
# 7.13
...

# 非方官方抽奖          ← 错别字「方」，原文如此
# 7.12
...
```

### 2.4 单条记录形态

- 列表项：`1) saber/兔子洞/...` 或纯奖品名
- 链接嵌在奖品名上，渲染为 Opus 卡片超链接
- HTML 中表现为：

```html
<a href="https://www.bilibili.com/opus/1222963088299393041"
   class="opus-text-rich-hl opus">
  <span>100元</span>
</a>
```

- `__INITIAL_STATE__` 中：

```json
{
  "type": "RICH_TEXT_NODE_TYPE_OPUS",
  "jump_url": "https://www.bilibili.com/opus/1222963088299393041",
  "rid": "1222963088299393041"
}
```

### 2.5 专属正则 / 解析策略

#### 策略 A：分区 + 链接（推荐）

1. 用标题行切分区块（优先级高于纯正则）：

```regex
^#\s*(充电抽奖|预约抽奖|互动抽奖)
^#\s*官方抽奖
^#\s*非方?官方抽奖
```

2. 在区块内提取链接：

```regex
https?://(?:www\.)?bilibili\.com/opus/(?P<dynamic_id>\d{18,19})
```

3. 分类映射：

| 当前区块 | lottery_type |
|----------|--------------|
| 预约抽奖 | 预约抽奖 |
| 官方抽奖、互动抽奖（父级下） | 互动抽奖 |
| 非官方抽奖 | 转发抽奖 |
| 充电抽奖 | 互动抽奖 |

#### 策略 B：INITIAL_STATE 遍历（更稳）

```python
# 伪代码
for node in walk(state):
    if node.type == "RICH_TEXT_NODE_TYPE_OPUS":
        yield node.rid, current_section_type
```

遍历正文节点时维护 `current_section` 变量，遇到 `TEXT` 标题含「预约抽奖」等则切换。

#### 排除规则

```regex
# 上期传送门、本期完、月卡推广等
上期传送门|本期完|\(本期完\)
```

### 2.6 实测规模

- 样本 cv51375456：WebFetch 可见约 **140** 个奖品条目
- 文首 1 个「上期」opus 链接需排除

## 3. DS-3：你的抽奖工具人（专栏 cv）

### 3.1 基本信息

- **空间**：https://space.bilibili.com/100680137/upload/opus  
- **样本**：[cv51406214](https://www.bilibili.com/read/cv51406214) —《【官方抽奖合集】（精选大奖版）7.13——7.17开奖部分！》  
- **并列栏目**：全部版、精选版、史上最全、临期/速看 等

### 3.2 更新特点

- **日更高产**：同一天可发 3～4 篇（精选版 + 全部版 + 日更大全）
- 长文前部有大段「工具人公告」（黑号、充电、关注提醒），与抽奖列表混杂
- 同时收录**官方**与**非官方（置顶）**抽奖
- 按**开奖日历**分块，而非按抽奖类型分块

### 3.3 排版结构

```text
【置顶抽奖①】
开奖日期：7.20
{奖品描述}
【抽奖啦！！】 → opus 链接
抽奖UP的名字和uid：【黑阳阳-】、【678778335】

——————————————————
【7.13日开奖部分】
1、→2026年07月13日 03:00→咪咕足球年费会员 * 10份→苏星河牛通的动态
2、→2026年07月13日 10:00→...→白银之城的动态
...

【7.14日开奖部分】
...

【7.15日开奖部分】
5、→...→https://www.bilibili.com/opus/1198149013518417976?spm_id_from=...
```

### 3.4 单条记录形态（两种）

**形态 A — 结构化箭头行（主流）**

```text
{序号}、→{YYYY年MM月DD日 HH:MM}→{奖品 * N份}→{链接文本}
```

链接文本常见：

- `{UP名}的动态` — Opus 卡片
- 动态标题原文 — Opus 卡片
- 极少数**裸 URL**（见上 opus/1198149013518417976）

**形态 B — 置顶块**

```text
【置顶抽奖①】
开奖日期：M.D
{多行奖品}
{标题链接}
抽奖UP的名字和uid：【名】、【uid】
```

### 3.5 专属正则

#### 链接提取（通用）

```regex
https?://(?:www\.)?bilibili\.com/opus/(?P<dynamic_id>\d{18,19})
```

#### 元数据提取（可选，便于展示）

```regex
(?P<idx>\d+)、→
(?P<lottery_time>\d{4}年\d{2}月\d{2}日\s+\d{2}:\d{2})→
(?P<prize>.+?)→
(?P<link_text>.+?)(?:​|\n|$)
```

#### 日期分块

```regex
【(?P<block>\d{1,2}\.\d{1,2}日开奖部分(?:（新日期）)?)】
```

#### 置顶块

```regex
【置顶抽奖[①②③\d]*】
开奖日期：(?P<pin_date>\d{1,2}\.\d{1,2})
```

#### 分类规则（无显式三分区）

| 条件 | lottery_type |
|------|--------------|
| 位于【置顶抽奖】块 | 转发抽奖 |
| 标题含「官方抽奖合集」「精选大奖」且条目有 lottery_notice | 互动抽奖 |
| `lottery_notice` 为空 | 转发抽奖 |
| 动态含 reserve | 预约抽奖 |

### 3.6 噪声

| 内容 | 处理 |
|------|------|
| 充电感谢名单、`【678778335】` 等 uid | 18 位数字可能误匹配；**只信 opus URL / INITIAL_STATE rid** |
| 大会员充电链接 | 非 opus，排除 |
| 工具人公告里的示例链接 | 通常无 opus 格式 |

### 3.7 去重建议

同一开奖日「精选版」⊂「全部版」⊂「史上最全」，**同一 cv 批次内按 dynamic_id 去重即可**；跨专栏选「精选版 + 临期/速看」优先，避免重复处理 4 篇日更。

## 5. DS-5：互动抽奖娘（Opus 图文帖）

### 5.1 基本信息

- **空间**：https://space.bilibili.com/3546776042736296/upload/opus  
- **样本**：[opus/1221421001768697897](https://www.bilibili.com/opus/1221421001768697897)（文底标注 cv51170671）  
- 标题：《新发抽奖合集 7月5日 78个抽奖》

### 5.2 更新特点（与其他源差异最大）

- 列表页在 upload/opus，但**点进去是 Opus 帖**，不是 `read/cv`
- **唯一用 Markdown 二级标题 `##` 明确三分区**的源（外加「充电抽奖」）
- 目录自动生成：`转发抽奖 / 充电抽奖 / 互动抽奖`
- 单条 = **奖品名即链接**，无开奖时间文本（时间需从目标动态 API 获取）

### 5.3 排版结构

## 9. 风险与待验证项

1. **DS-5 预约抽奖分区**：当前样本仅见转发/充电/互动，需在后续轮询中确认「预约抽奖」标题的 HTML 形态是否与 `## 预约抽奖` 一致。  
2. **API 风控**：`x/article/metas`、`x/space/arc/search` 可能 412/-352，生产环境需 Cookie + 限速。  
3. **t.bilibili.com 跳转**：需在实现期验证短链 ID 是否恒等于 opus dynamic_id（目前样本均为 19 位，与 opus 一致）。  
4. **「非官方」判定**：最终必须依赖 `lottery_notice`，不能仅靠数据源分区。
