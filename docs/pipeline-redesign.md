# 一键更新活动链接 — 流水线重设计需求文档

> 触发入口：控制台「一键更新活动链接」按钮（`refresh_all`）  
> 范围：**6 个数据源（DS-1～DS-6）**；不含监控用户（WATCH）  
> 状态：**需求已拍板**（实施分阶段，见「实施策略」）

---

## 实施策略（分阶段）

> **当前阶段原则（用户 2026-07-15 确认）：**

1. **保留旧逻辑**：起初继续沿用现有代码路径、旧策略与旧实现；新流水线 **增量开发**，不一次性推翻。
2. **旧数据不动**：本地已保存的活动链接 / `classified` / `enriched` 等 **暂不迁移、不批量重写**；新规则 **仅作用于本次新进入的链接**。
3. **单一活动库（§16）**：作为后续重构目标；落地时需兼容读取旧库，**不强制本次迁移历史数据**。
4. **「刷新活动状态」按钮（§18）**：**本期不实现**；相关全库状态逻辑延后。

---

## 背景与目标

重理顺「一键更新」五步流水线：采集 → 去重 → 分类（含排除）→ 详情 → 状态。各步职责单一，失败策略明确。

已知待解决问题：假阳性转发抽奖、hint 盲目信任、skipped 落库混乱、网络失败与链接失效未区分。

---

## 核心约束（全局）

### 本地活动链接：读与写的边界

| 操作 | 是否允许 | 说明 |
|------|----------|------|
| **读取**本地已有活动 ID（去重比对） | ✅ Step 2 | 只读，判断「本地是否已有」；**不修改**任何已存活动 |
| **写入 / 更新 / 删除**本地已有活动 | ❌ 全程禁止 | 启动流水线后，对本地已存活动 **零写入** |
| **追加**新活动到本地 | ✅ **仅 Step 5 最后** | 且 **只有走完 Step 1～5 全流程** 的才保存 |

### 五条硬性规则

1. **只处理新链接**：Step 2～5 的对象仅是本次 `new_unique_links`；**不**对本地已存活动做分类、补详情、改状态。
2. **skipped 不落库**：充电 / 非抽奖 / 失效等在中途 `skipped` 的，**不进入本地**。
3. **落库 = 流水线最后一步**：Step 5 末尾 **一次性** 将「已通过全流程」的活动写入本地；Step 1～4 **不写活动库**。
4. **无新物料即结束**：6 源容器均未变，或去重后无新链接 → 正常结束，**本地活动库零变更**。
5. **全库状态刷新延后**：「刷新活动状态」本期不实现（§18）。

> **说明**：Step 1 会更新各数据源的 **容器链接记录**（用于下次对比专栏/视频是否更新），这是对 **容器书签** 的写入，**不是**对本地 **活动链接库** 的写入。

---

## 流水线总览

```
[Step 1 采集] → [Step 2 去重] → [Step 3 分类] → [Step 4 详情] → [Step 5 状态 + 落库]
     ↑                    ↑                                              ↑
     │                    │                                              └── 唯一写入本地活动库的步骤
     │                    └── new_unique_links 为空 → 结束（本地活动库不变）
     └── 6 源容器均未变 → 结束
```

Step 1～4 中间结果均在 **内存** 中流转；**只有** 走完 Step 5 的活动才 **追加** 到本地活动库。

---

| 场景 | 行为 |
|------|------|
| 链接失效（404 / 动态已删除） | `skipped`，继续（不落库） |
| B 站限流、网络超时、Cookie 失效 | **报错，停止整条流水线** |
| 奖品 / 热度确实无法获取（非网络原因） | **报错，停止整条流水线** |
| 非抽奖 / 充电专属 | `skipped`，继续（不落库） |
| 任一数据源 Step 1 检查失败 | **报错，停止整条流水线** |

## Step 1：数据源采集（只爬，不处理）

### 容器链接（统一表述）

各数据源的「容器」统一称为 **容器链接**，包括：

| 源 | 容器类型 |
|----|----------|
| DS-1 | 最新 **视频**（简介区链接） |
| DS-2～DS-6 | 最新 **专栏 / Opus** |

### 逻辑（每源独立）

1. 爬取该 UP **最新容器链接**
2. 与本地 **上次保存的容器链接** 对比
3. **一致** → `unchanged`，不爬正文
4. **不一致** → 更新本地容器记录，从新容器正文爬取 **全部** 活动链接
5. **不做** 分类、去重、hint、skipped

### 输出与终止

- 6 源全部 `unchanged` → **结束流水线**
- 否则输出 `raw_links` 进入 Step 2

---

## Step 2：去重

### 第一次去重 — 与本地库比对

- 遍历 Step 1 的 `raw_links`
- 在 **本地已保存的全部有效活动链接** 中查找
- 已存在 → 跳过；不存在 → 进入候选集

### 第二次去重 — 候选集内部

- 按 `dynamic_id` 去重，每个 ID 只保留一条
- **多源爬到同一链接**：去重步骤消除重复即可，**无需保留来源信息**

### 输出与终止

- `new_unique_links` 为空 → **结束流水线**（无上游物料）
- 否则传入 Step 3

---

## Step 3：分类与排除

### 五类输出

| 类型 | 判定 | 下游 |
|------|------|------|
| 互动抽奖 | API `lottery_notice` (bt=1) | → Step 4 |
| 预约抽奖 | API `reserve` (bt=10) | → Step 4 |
| 充电抽奖 | API 充电特征 (bt=12) | `skipped` |
| 转发抽奖 | LLM `is_lottery=true`（含评论抽奖） | → Step 4 |
| 非抽奖活动 | LLM `is_lottery=false` | `skipped` |

### 判定顺序

```
访问详情 → 404? skipped(失效)
→ 充电? skipped
→ 互动? 
→ 预约?
→ LLM 是否抽奖? 是→转发 / 否→skipped(非抽奖)
```

### 失败策略

- 404 → `skipped`，继续
- 网络 / LLM 服务失败 → **停流水线**

---

## Step 4：活动详情爬取

### 输入

Step 3 三类未 `skipped` 的新链接。

### 字段

| 字段 | 必填 | 来源 |
|------|------|------|
| 奖品内容 | **是** | 互动/预约：API；转发：LLM |
| 开奖时间 | 否 | 互动/预约：API；转发：LLM；预约=开播时间 |
| 热度值 | **是** | 互动/转发：转发量；预约：预约量 |

### 规则

- 开奖时间缺失 → **流水线执行时刻（北京时间）+ 180 天**
- 热度 API **报错** → 停流水线；正常返回 **0** → 接受
- 奖品或热度确实无法获取 → 停流水线
- **已过期的新活动仍走本步**，不在此步跳过

---

## Step 5：状态标记 + 落库（流水线最后一步）

本步两件事，**顺序执行**：

1. **计算状态**（仅针对本次走完 Step 4 的活动）
2. **写入本地活动库**（仅上述活动；**流水线中唯一落库点**）

### 谁会被保存？

**同时满足** 以下全部条件才写入本地：

- 通过了 Step 3（互动 / 预约 / 转发，非 `skipped`）
- 通过了 Step 4（奖品、热度齐全；开奖时间可缺省补 +180 天）
- 完成了本节状态计算

未满足任一条（含 Step 3 的 `skipped`、Step 4 失败导致流水线中止）→ **不写入本地**。

### 维度 A — 参与状态（互斥）

`未参加` | `已参加` | `已结束`

- 新链接默认 `未参加`
- 若已过开奖时间且未参加 → **`已结束`**（不能标 `未参加`）

### 维度 B — 开奖标签（互斥，可空）

`即将开奖` | `已开奖` | **空值**（不在窗口内）

- 不在「即将开奖」「已开奖」时间窗口内 → **空值**
- **首次入库约束（§17）**：新活动默认 `未参加`，故 **首次入库不可能出现 `已开奖`**（`已开奖` 需已参加 + 开奖后 3 天内）；仅在未来实现「刷新活动状态」或用户参加后才可能出现

### 时间规则（开奖时间 T，当前时间 now）

| 条件 | 参与状态 | 开奖标签 |
|------|----------|----------|
| now ∈ [T−3天, T) | 未参加 / 已参加 | `即将开奖` |
| now ∈ [T, T+3天] 且 已参加 | 已参加 | `已开奖` |
| now > T 且 未参加 | `已结束` | 空值 |
| now > T+3天 且 已参加 | `已结束` | 空值 |
| 其他 | 未参加 / 已参加 | 空值 |

### 落库

- **追加**写入本地活动库（单一活动库，见 §16）；**不修改、不删除** 任何已存记录
- 旧数据保持不动；新记录仅来自本次全流程产物

---

## 不在本流水线内 / 本期不做

| 能力 | 入口 | 说明 |
|------|------|------|
| 监控用户转发动态 | `refresh_watch` | 独立流水线，规则另定 |
| 全库状态刷新 | `refresh_status` | **本期不实现（§18）** |
| 手动删除失效/非活动/充电链接 | 用户运维 | 旧数据暂不动，由用户手动维护 |
| 历史数据迁移 / 批量修补 | 运维脚本 | 旧链接暂不迁移 |

## 已拍板结论汇总

| 编号 | 结论 |
|------|------|
| §1 | 统一表述为 **容器链接**（视频 + 专栏） |
| §2 | 本地库 = 已持久化有效活动；`skipped` **不落库** |
| §3 | 多源重复在去重步消除，**不保留来源** |
| §4 | 无新链接 → **结束流水线**；**不做任何全库操作** |
| §5 | 评论抽奖 → LLM 判定为抽奖则归 **转发抽奖** |
| §6 | `skipped` **不写入本地** |
| §7 | 热度 0：API 报错停流水线；真实 0 接受 |
| §8 | +180 天基准 = **流水线执行时北京时间** |
| §9 | 已过期新链接 **仍走全流程**，最终标 **`已结束`** |
| §10 | 窗口外开奖标签 = **空值** |
| §11 | **API 优先**（互动/预约/充电），其余 LLM 判抽奖 |
| §12 | 任一数据源 Step 1 失败 → **停整条流水线** |
| §13 | 容器变更但无新链接 → **仍更新容器记录**，再去重；无新链接则结束 |
| §14 | 已过期的新抽奖 → **走完流水线并写入本地**，标 `已结束` |
| §15 | 非抽奖重复爬到 → **接受**；靠流水线筛选，不落库 |
| §16 | 落库目标为 **单一活动库**；**仅 Step 5 追加**；旧库暂不迁移 |
| §17 | **首次入库不可能 `已开奖`**；可出现 `即将开奖` / `已结束` / 空值 |
| §18 | **本期不实现**「刷新活动状态」按钮 |

## 附录：与现实现对照

| 环节 | 现实现 | 新设计 |
|------|--------|--------|
| 范围 | 合并后可能触及全库状态 | **仅新链接** |
| 采集 | 写 hint | 只爬链接 |
| 去重 | merge 含 WATCH | 两次去重，无来源 |
| 分类 | hint 直通 + 默认转发 | API + LLM，非抽奖 skipped |
| 落库时机 | Step 3/4 过程中可能写 classified/enriched | **仅 Step 5 末追加** |
| 本地旧活动 | 可能被 merge/refresh 触及 | **全程只读（去重）或零接触** |
