## 4. 对五个项目的机会、风险和行动建议

### DPMS

沿现有真实执行系统增加 `ExecutionSession`，先只做观察、协作、审批和 handoff，不改变 real-run 安全链。

### Prompt Performance Engine

增加 environment snapshot + deterministic verifier；再做 BudgetSweep，测单位预算成功率，而不只是单一模型分数。

### KIS

增加 `ContextRef`，让经过 canonical/信任边界筛选的 KnowledgeCard 进入 Agent Session，而不是整个知识库直接注入 Prompt。

### ClipVault

未来 ContextEnvelope 可以预留 `session_ref`，但敏感 payload 必须保持不持久化、TTL bounded、one-shot/replay protection。

### Binggo (`bil-1`)

Binggo 当前已经有本地 B 站抽奖闭环、任务状态机、定时调度、多账号池、风险友好策略、本地 Web UI 与 MCP stdio 扩展。它很适合当 **Agent Control Surface 的小型试验场**，但不应该让 LLM 绕过现有 deterministic executor 直接做真实点赞/关注/转发/评论。

建议优先扩展低风险 MCP：

```text
inspect_activity
explain_rule
preview_action_plan
inspect_account_risk
inspect_scheduler
inspect_evidence
```

推荐执行模型：

```text
User / Shared Session
        ↓
Agent 解释与规划
        ↓
Action Preview
        ↓
Human Approval / Existing Gate
        ↓
Binggo deterministic executor
        ↓
Evidence / Result
```

这样可以验证 Agent 的解释、规划、上下文读取和多人协作价值，同时不破坏已有调度、风控、限速和凭据边界。

UI 方面也值得从“聊天窗口”转向执行面板：在现有时间槽、活动列表、任务状态上叠加 `plan / risk / approval / evidence`，而不是单独再造一个 Chat 页面。

## 今日判断

今天最有价值的变化不是“Agent 更自治”，而是 Agent 执行开始成为多人可见、可预算、可审批、可交接的共享状态。

五个项目可逐渐共享：`ExecutionSession / ContextRef / ExecutionBudget / PolicyDecision / TrustContext / Artifact / Evidence`。

Binggo 最适合先验证其中最小闭环：**Agent 负责理解与解释，现有确定性系统负责真实执行，Evidence 负责证明发生了什么。**
