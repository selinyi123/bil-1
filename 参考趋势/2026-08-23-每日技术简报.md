# 每日技术简报｜2026-08-23

## 今日结论

今天最值得追踪的不是新模型，而是 Agent Runtime 的两个基础能力正在快速成熟：

1. **Runtime Event Log / durable authority**：执行日志不再只是观测数据，而开始成为 session、恢复、UI、上下文投影和审计的权威来源。
2. **Cost / cache / budget engineering**：缓存命中、cache write/read、token、tool-call 上限和 per-run spending 正逐渐成为 Agent 配置的一部分，而不是账单后的统计。

对 DPMS / PPE / KIS / ClipVault / Binggo 的共同启示是：下一阶段最值得共享的 primitive 不应继续扩成新的 Agent 协议，而应围绕 `ExecutionRecord / ContextRef / CostProfile / PolicyDecision / Evidence` 建模。

## 2. 今天最值得看的开源项目

### Apache Maka

GitHub： https://github.com/apache/maka

Maka 的核心思路是 **Log is the Runtime**。模型消息、Tool Call、Tool Result、permission decision、termination fact 进入 append-only Runtime Event Log；Session、UI、Context、Recovery 则是 projection。

### Vercel Labs / fx

GitHub： https://github.com/vercel-labs/fx

`fx` 是 Zig 写的极小型、可嵌入 coding-agent harness，支持 Skills、MCP、subagents，并提供 WASM 嵌入方向。近期 PR 集中在权限一致性、destructive action 审批、subagent 退休、认证 ownership、goal tracking 和 MCP timeout。

### Windows AppContainer sandbox

Maka 0.1.11 加入 brokered Windows AppContainer sandbox 和更严格的 IPC/ACL。对于本地 Windows 自动化工具，这是非常直接的参考。

## 3. 技术趋势与架构参考

### Agent UI 从“聊天记录”转向“执行 Trace”

比 chat bubbles 更有价值的主视图是：

```text
Run
├ state transition
├ action attempt
├ retry/backoff
├ external response class
├ risk/policy decision
├ evidence
└ final result
```

这种 UI 更适合 scheduler / automation / local agent 产品，也更容易做恢复与审计。

### Context / History / Evidence 三层分离

```text
Evidence → 永久执行事实
History  → 可浏览交互
Context  → 当前 inference 的有限工作集
```

### Agent 只能做计划，不代表它应该拥有执行 authority

Binggo 这类涉及真实平台互动的系统尤其应保持：

```text
LLM interpretation / planning
        ↓
Action Preview
        ↓
policy / user gate
        ↓
deterministic executor
        ↓
state readback + evidence
```

## 4. 对五个项目的建议

### DPMS

新增只读 `ExecutionRecord` projection，复用现有 event/audit/evidence，不改变 real-run authority。

### Prompt Performance Engine

新增 `CostProfile + CachePolicy`，把 quality / reliability / cost 一起评估。

### KIS

新增 `ContextSelection` artifact，记录一次 inference 使用的精确知识版本。

### ClipVault

不扩功能边界，继续作为可信本地 Context Source / Transport。

### Binggo

Binggo 目前已有 local API、MCP、scheduler、job state machine 和确定性参与链，是最适合低成本验证 Agent Control Surface 的项目。

今天建议实现只读：

```text
GET /api/runs/{id}/trace
```

至少返回：

```text
run_id
job_type
state transitions
action attempts
retry/backoff
risk decisions
external response class
evidence refs
started_at / finished_at
```

然后 MCP 增加：

```text
inspect_run
explain_failure
preview_action_plan
inspect_scheduler
```

第一阶段明确不增加可直接触发点赞/关注/收藏/转发/评论的 Agent 写工具。

机会：可以快速验证“Execution Trace UI + Agent explanation”的实际价值，并且对现有确定性执行链影响很小。

风险：真实互动动作仍必须由现有 executor、账号风控、限速和状态回读控制；LLM 不能成为 authority。

## 今日最终判断

今天最值得稳定下来的三个跨项目对象是：

```text
ExecutionRecord  → 这次执行发生了什么？
ContextSelection → 模型当时实际看到了什么？
CostProfile      → 为这次结果付出了多少资源？
```

对 Binggo 而言，最值得先验证的是第一个。先让系统把“发生了什么”表达清楚，再让 Agent 解释、诊断和预演；不要反过来先把真实写权限交给 Agent。
